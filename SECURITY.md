# Безопасность Ноты 59

## Текущее состояние

В main.py есть фильтр ссылок, начальная проверка прав и команды владельца /security и /security_ids. Проверка работающего экземпляра на BotHost не выполнена. Автоматические муты и баны выключены. Неверный ID группы или отсутствие прав оставляют фильтр выключенным, не останавливая каталог.

## Проверки GitHub

Workflow запускает проверку синтаксиса и unittest без BOT_TOKEN. В тестах обращения к Telegram подменяются mock-объектами; это не полноценная проверка Telegram и хостинга. Actions закреплены по commit SHA, права workflow ограничены contents: read. Прохождение тестов нужно проверить в Actions после коммита. Workflow сам по себе не блокирует merge или развёртывание: required checks настраиваются отдельно.

Dependabot настроен на еженедельные предложения обновлений pip и GitHub Actions. Автоматического слияния нет. Эта конфигурация не означает, что Dependabot alerts, security updates, secret scanning и push protection уже включены в настройках репозитория. Их состояние необходимо проверить отдельно в Settings / Security.

## Секреты

BOT_TOKEN хранить в секретных настройках хостинга, не в GitHub. .gitignore не удаляет ранее опубликованные файлы и секреты из истории. При утечке токен нужно отозвать и заменить через официальный BotFather, затем обновить секрет на хостинге. Пароли и коды входа никому не передавать.

## Ручная проверка перед приглашением участников

1. Убедиться, что хостинг загрузил нужный коммит.
2. Открыть личный чат бота, отправить /start и /security.
3. В группе отправить /security_ids от аккаунта владельца, не анонимно, и сверить ID.
4. Выдать боту только необходимые права, в том числе удаление сообщений.
5. Проверить разрешённую, запрещённую, скрытую ссылку, подпись к фото и редактирование от обычного участника. Администраторы исключены из фильтра.
6. Не проверять ручной /ban на реальном покупателе.

## Ограничения и дальнейшие этапы

Постоянный журнал ожидает проверки сохранности диска BotHost. Контроль my_chat_member, миграция ID, /report, ручные предупреждения и антифлуд в режиме уведомлений пока не реализованы. QR-коды, ссылки в изображениях и личная переписка мошенников с покупателями текущим фильтром не контролируются.

Не публикуйте токены или личные данные участников в публичных Issues.
